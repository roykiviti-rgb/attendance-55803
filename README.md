# רישום נוכחות ב-QR — יסודות המימון (55803)

מערכת נוכחות להרצאות: לפני כל הרצאה מדפיסים דף קודי QR, גוזרים ומחלקים פיסה אחת לכל סטודנט. הסטודנט סורק, בוחר את שמו ונרשם כנוכח.

- כל קוד **חד-פעמי**: אחרי רישום אחד, סריקה חוזרת נדחית.
- הקוד **אנונימי**: אפשר לרשום איתו כל סטודנט מהרשימה, אבל רק פעם אחת.
- הקוד **תקף 24 שעות** מרגע ההפקה (ניתן לשינוי), ורק להרצאה שעבורה הופק.
- **אי אפשר לזייף קוד**: כל קוד חתום במפתח סודי שנמצא רק אצל המרצה וב-Worker.

## רכיבים

| רכיב | איפה רץ | תפקיד |
|---|---|---|
| `generate.py` | המחשב של המרצה | יוצר קודים חתומים ו-PDF להדפסה |
| `index.html` | GitHub Pages | העמוד שהסטודנט רואה אחרי הסריקה |
| `worker/` | Cloudflare Workers | בודק חתימה, תוקף ושם, מחזיר את רשימת השמות ורושם ב-Firestore |
| `students.json` | רק במחשב של המרצה | רשימת הסטודנטים. נארזת לתוך ה-Worker בזמן הפריסה |

### פרטיות שמות הסטודנטים

`students.json` **לא** עולה ל-GitHub (הוא ב-`.gitignore`) ולא נמצא באתר הציבורי. הרשימה נמצאת רק בתוך ה-Worker, והוא מחזיר אותה רק למי ששולח קוד תקף: חתום, בתוקף ועוד לא נוצל. מי שנכנס לאתר בלי קוד, או עם קוד שכבר שומש, לא רואה אף שם. בפועל רק מי שקיבל דף בכיתה רואה את הרשימה.

**שפה:** האתר וה-PDF באנגלית, כי חלק מהסטודנטים לא קוראים עברית. השמות ב-`students.json` כתובים באנגלית, כפי שהם מופיעים בייצוא המשתתפים מ-Moodle ("First name" + "Last name", סטודנטים בלבד).

**שינוי ברשימה** (סטודנט הצטרף או עזב): ערכו את `students.json` והריצו שוב `npx wrangler deploy` מתוך התיקייה `worker`. בלי פריסה מחדש, השינוי לא ייכנס לתוקף.
| Firestore | Firebase | אחסון בלבד: `used` (קודים שנוצלו) ו-`attendance` (רישומים) |

## ⚠️ אזהרה: המפתח הסודי

הקובץ `secret.key` ומפתח ה-service account של Firebase (קובץ JSON) **אסור שיגיעו ל-GitHub**. גם `students.json` לא עולה לשם, מטעמי פרטיות (ראו למעלה). מי שמחזיק את `secret.key` יכול לייצר קודי נוכחות כרצונו, ומי שמחזיק את מפתח ה-service account יכול לקרוא ולשנות את כל רישומי הנוכחות.

- שני הקבצים כבר מופיעים ב-`.gitignore`. **לפני כל commit** הריצו `git status` ובדקו שהם לא מופיעים ברשימה.
- המפתחות לא נכתבים בשום קובץ קוד ולא ב-`wrangler.toml`. ב-Worker הם נשמרים רק כ-Secrets.
- אם מפתח דלף: צרו `secret.key` חדש (מחקו את הישן והריצו `--init-secret`) ועדכנו את ה-Secret ב-Worker. כל הקודים הישנים יפסיקו לעבוד. ל-service account: מחקו את המפתח ב-Google Cloud Console וצרו חדש.

## הקמה (פעם אחת)

### דרישות מוקדמות

- Python 3.9 ומעלה, ואז: `pip install qrcode reportlab`
- Node.js 18 ומעלה (בשביל `npx wrangler`)
- חשבונות: GitHub, Cloudflare (חינמי), Google/Firebase (תוכנית Spark החינמית מספיקה)

### 1. GitHub Pages

1. צרו repo חדש ב-GitHub (למשל `attendance-55803`) ודחפו אליו את התיקייה הזאת (אחרי שבדקתם את `git status`, ראו אזהרה למעלה).
2. ב-repo: **Settings → Pages → Source: Deploy from a branch**, בחרו `main` ותיקייה `/ (root)`.
3. כתובת האתר תהיה `https://<user>.github.io/<repo>/`. עדכנו אותה ב-`generate.py`, במשתנה `BASE_URL` (עם `/` בסוף).

### 2. Firebase / Firestore

1. היכנסו ל-[console.firebase.google.com](https://console.firebase.google.com) וצרו פרויקט חדש (אפשר לוותר על Google Analytics).
2. **Build → Firestore Database → Create database**. בחרו מיקום (למשל `me-west1` בתל אביב, או `eur3`) ו-**production mode**.
3. בלשונית **Rules** הדביקו את התוכן של `firestore.rules` ולחצו **Publish**. הכללים חוסמים כל גישה ישירה מדפדפן. ה-Worker ניגש עם service account, שלא כפוף לכללים.

### 3. Service account

1. בפרויקט ב-Firebase: **⚙️ Project settings → Service accounts → Generate new private key**.
2. יורד קובץ JSON. שמרו אותו בשם `service-account.json` **בתיקייה הזאת** (הוא ב-`.gitignore`) או מחוץ לה.

### 4. המפתח הסודי

```
python generate.py --init-secret
```

הפקודה יוצרת את `secret.key` (פעם אחת בלבד). אל תיצרו אותו ידנית עם `>` ב-PowerShell: זה כותב את הקובץ בקידוד UTF-16 והחתימות לא יתאימו.

### 5. Cloudflare Worker

```
cd worker
npx wrangler login
```

1. ב-`worker/wrangler.toml` עדכנו את `ALLOWED_ORIGIN` לכתובת ה-GitHub Pages, **רק ה-origin, בלי נתיב**: `https://<user>.github.io`.
2. העלו את שני ה-Secrets (מתוך התיקייה `worker`):

   PowerShell:
   ```
   Get-Content ..\secret.key -Raw | npx wrangler secret put HMAC_SECRET
   Get-Content ..\service-account.json -Raw | npx wrangler secret put FIREBASE_SERVICE_ACCOUNT
   ```
   bash / macOS:
   ```
   npx wrangler secret put HMAC_SECRET < ../secret.key
   npx wrangler secret put FIREBASE_SERVICE_ACCOUNT < ../service-account.json
   ```
   (wrangler ייצור את ה-Worker אם הוא עוד לא קיים.)
3. פרסו:
   ```
   npx wrangler deploy
   ```
   בסוף תודפס כתובת כמו `https://attendance-55803.<account>.workers.dev`.
4. עדכנו את הכתובת הזאת ב-`index.html`, במשתנה `WORKER_URL`, ודחפו ל-GitHub. הכתובת אינה סוד.

## לפני כל הרצאה

**הדרך הקלה (Windows):** לחיצה כפולה על **`הפקת קודים להרצאה.bat`**. ייפתח חלון עם לוח שנה: בוחרים את תאריך ההרצאה ואת מספר הקודים ולוחצים "צור קודים". ה-PDF נפתח לבד.

**משורת הפקודה:**

```
python generate.py --date 2026-10-20
```

נוצר הקובץ `out/attendance-55803-2026-10-20.pdf` עם 17 קודים, 9 לעמוד (2 עמודים).

| פרמטר | ברירת מחדל | משמעות |
|---|---|---|
| `--date` | היום | תאריך ההרצאה, ממנו נבנה מזהה ההרצאה `55803-YYYY-MM-DD` |
| `-n` | 17 | מספר קודים. מומלץ להדפיס כמה עודפים |
| `--hours` | 24 | שעות תוקף **מרגע ההפקה** |
| `--layout` | `3x3` | קודים לעמוד: `3x3`, `2x2`, או `1x1` (קוד אחד לעמוד) |
| `-o` | `out/…pdf` | נתיב קובץ הפלט |

**שימו לב לתוקף:** הוא נספר מרגע ההפקה, לא מתחילת ההרצאה. אם מפיקים את הקודים ערב לפני, ייתכן שהם יפוגו לפני סוף ההרצאה. הפיקו ביום ההרצאה, או הוסיפו `--hours 36`.

**הדפסה:** הדפיסו בגודל 100% ("Actual size", לא "Fit to page"). גזרו לאורך הקווים המקווקווים. כל פיסה ממוספרת (`#1`, `#2`…) בפינה, כדי שיהיה קל לספור.

הרצה חוזרת של הפקודה יוצרת קודים **חדשים**. הקודים שהודפסו קודם נשארים תקפים עד שיפוג תוקפם. אל תשאירו קבצי PDF עם קודים תקפים במקומות משותפים. התיקייה `out/` ב-`.gitignore`.

## צפייה בנוכחות

ב-Firebase Console: **Firestore Database → Data → `attendance`**. לכל רישום יש מסמך עם השדות:

- `name`: שם הסטודנט
- `lec`: מזהה ההרצאה (למשל `55803-2026-10-20`)
- `timestamp`: זמן הרישום
- `id`: מזהה הקוד

לסינון לפי הרצאה: לחצו על סמל הסינון ליד האוסף, ובחרו `lec` == `55803-2026-10-20`.

## בדיקת תקינות אחרי ההקמה

1. הפיקו 3 קודים (`python generate.py -n 3 --layout 2x2`) וסרקו אחד מהם בטלפון. הרישום אמור להצליח ולהופיע ב-`attendance`.
2. סרקו את אותו קוד שוב (רצוי מטלפון אחר). אמורה להופיע ההודעה "קוד כבר שומש".
3. ערכו ידנית ב-URL תו אחד ב-`id`. אמורה להופיע ההודעה "קוד לא תקין".
4. ודאו שגישה ישירה ל-Firestore נחסמת (צריך לחזור `403 PERMISSION_DENIED`):
   ```
   curl "https://firestore.googleapis.com/v1/projects/<project-id>/databases/(default)/documents/attendance"
   ```
5. ב-repo ב-GitHub ודאו ש-`secret.key`, קובץ ה-service account ו-`students.json` לא מופיעים.
6. פתחו את כתובת האתר בלי פרמטרים, או עם קוד שכבר שומש. אף שם לא אמור להופיע.

## מגבלה חשובה

המערכת מונעת זיוף קודים ושימוש כפול באותו קוד, אבל **לא יכולה למנוע** מסטודנט לצלם את הפיסה שקיבל ולשלוח אותה לחבר שלא נמצא בכיתה, כדי שהחבר יירשם (או שסטודנט נוכח יירשם בשם חבר נעדר). אף פתרון שמבוסס רק על QR לא פותר את זה.

כמה דברים מצמצמים את הבעיה: לחלק בדיוק פיסה אחת לכל סטודנט נוכח, ולהשוות את מספר הרישומים למספר הנוכחים בפועל. אם נדרשת אכיפה מלאה, צריך שכבה נוספת, כמו קוד מתחלף שמוצג על המקרן בכיתה בלבד, או אימות מיקום.

גם בחירת שם שגויה (בטעות) נרשמת כפי שהיא. במקרה כזה אפשר לתקן או למחוק את המסמך ידנית ב-Firebase Console.
